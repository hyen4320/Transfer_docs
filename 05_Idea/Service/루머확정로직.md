# 루머 확정 로직

## 개요

X(트위터) 기자 게시물에서 파싱된 이적 루머(`RUMOR`)를 Admin이 수동으로 확정/부인하는 흐름.
Gemini 파싱이 1차 자동 분류를 하고, Admin 엔드포인트로 최종 확정.

---

## 흐름

```
X 트윗 수집
  → Gemini 파싱 → TransferNews 생성 (status: RUMOR / CONFIRMED / DENIED 등)
  → Admin이 수동 확정
      PATCH /api/admin/news/{newsId}/confirm
          ↓
      TransferNews.status 변경
      Verification upsert (is_confirmed, source_url, confirmed_by)
      Player.currentClub 동기화
```

---

## 엔드포인트

```
PATCH /api/admin/news/{newsId}/confirm
Header: X-Admin-Token: <ADMIN_SECRET>
Body:
{
  "status": "CONFIRMED",         // RUMOR | CONFIRMED | DENIED | LOAN | CONTRACT_EXTENSION | FREE_AGENT
  "sourceUrl": "https://...",    // 공식 발표 URL (선택)
  "confirmedByJournalistId": 1   // 확정 보도 기자 ID (선택)
}
```

---

## 상태별 처리

| status | Verification.isConfirmed | Player.currentClub |
|---|---|---|
| CONFIRMED | true | toClub, CONTRACTED |
| CONTRACT_EXTENSION | true | toClub, CONTRACTED |
| LOAN | true | toClub, LOANED |
| FREE_AGENT | true | null, FREE_AGENT |
| DENIED | false | 변경 없음 |
| RUMOR | Verification 생성 안 함 | 변경 없음 |

## 인증

`AdminInterceptor`가 `/api/admin/**` 전체를 보호.
`X-Admin-Token` 헤더 = `.env`의 `ADMIN_SECRET` 값.

---

## 결정 사항

- **수동 위주 + Gemini 보조**: Gemini 파싱이 초안 status를 정하고, Admin이 override
- **자동 확정 (기자 신뢰도 기반)**: 데이터가 쌓인 후 고려 (미구현)
- **UnregisteredMention 큐**: 보류 — 선수 DB 충분히 쌓인 후 구현

---

## 연관

- `CredibilityMetric.accuracy_score` = 확정된 뉴스 / 전체 뉴스 → Verification 데이터에 의존
- `Verification` 테이블이 쌓여야 기자 공신력 점수 계산 가능
