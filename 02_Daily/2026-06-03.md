#### BUG 1 — 6월에 수집된 소식이 25/26으로 태깅됨

**위치**: `PostParsingServiceImpl.determineSeason()` (line 181~192)

```java
int year = now.getYear() % 100;        // 2026 → 26
if (month >= 3 && month <= 5)          // 3~5월 → 26+27 = 53 (26/27)
    return (short)(year + (year + 1));
return month >= 7
    ? (short)(year + (year + 1))       // 7월~ → 53 (26/27)
    : (short)((year - 1) + year);      // 그 외 → 25+26 = 51 (25/26)
```

- 3~5월 → **53** (26/27), 7월~ → **53** (26/27)
- **6월만 else로 빠져 → 51 (25/26)** ← 구멍(gap)
- 오늘 6월에 수집되는 소식이 전부 `season = 51`로 저장됨 (`PostParsingServiceImpl.java:91` → `.season(season)` line 124)
- `determineWindow()`는 6월을 `SUMMER`로 판단 → **window=SUMMER인데 season=직전(51)** 불일치
- **수정 방향**: 6월을 7월과 같은 분기로 합치기 (`month >= 6` 또는 `month >= 3` 통합)

> 참고: FE `transferWindow.ts:33`도 `month >= 7` 기준이라 6월=51로 동일하게 어긋남. 단 FE엔 3~5월 다음시즌 케이스가 없어 **3~5월엔 BE=53 / FE=51로 서로 불일치**. 전환 기준을 FE/BE 한 곳으로 통일 필요

#### BUG 2 — 25/26이 "현재 시즌"으로 분류돼 시간순 정렬됨

> 정정: 지난 시즌 이적료순 정렬 로직은 **이미 존재함** (앞선 "쿼리가 전부 시간순" 가설은 틀림). 24/25는 이미 이적료순으로 잘 나옴

**위치**: 뉴스 정렬은 FE가 `sort` 파라미터로 제어 (`news.ts:24`), BE는 받은 값대로 정렬

- `useNews.ts:19` / `useNewsInfinite.ts:18`:
  ```ts
  isPast = season < CURRENT_SEASON || (season === CURRENT_SEASON && !WINDOW_IS_OPEN);
  sort   = isPast ? 'feeEur,desc' : 'publishedAt,desc';
  ```
- 6월 현재 `getTransferWindowState()` → `CURRENT_SEASON = 51 (25/26)`, `WINDOW_IS_OPEN = true`
  - 24/25(49): `49 < 51` → past → **feeEur,desc** ✓ (실제로 이적료순 맞음)
  - 25/26(51): `51 < 51` 거짓 + 윈도우 열림 → past 아님 → **publishedAt,desc** (시간순)
- **정렬 로직 문제가 아니라 "현재 시즌" 경계가 25/26로 잡혀 있어 25/26이 live 취급됨** → BUG 1과 동일한 뿌리
- 추가 latent 버그: `CountryMapPage.tsx:119,130`이 **`localSeason === 51` 하드코딩**
  ```ts
  const sort = localSeason === 51 ? 'publishedAt,desc' : 'feeEur,desc';
  ```
  - 경계가 51에 박혀 있어, 시즌 경계를 고쳐도 25/26은 계속 시간순으로 남음 → `CURRENT_SEASON` 동적 비교로 교체 필요
- **수정 방향**: 시즌 경계(BUG 1)를 26/27(53)로 바로잡으면 `useNews`/`useNewsInfinite`는 25/26을 past로 인식해 자동 이적료순 전환. 단 `CountryMapPage` 하드코딩 51은 별도로 동적 비교로 교체해야 함
