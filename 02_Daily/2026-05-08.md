### Priority 5 — 안드로이드 웹앱 개발 전략

#### 선택지 비교

| 방식 | 난이도 | 앱스토어 출시 | 네이티브 기능 | 권장 여부 |
|---|---|---|---|---|
| **PWA** | 쉬움 | 불가 (설치는 가능) | 제한적 | 1단계로 적합 |
| **TWA (Trusted Web Activity)** | 보통 | 가능 (Play Store) | PWA 수준 | 메인 전략 |
| **Capacitor** | 보통 | 가능 | 카메라/알림 등 | 네이티브 필요 시 |
| **React Native 재작성** | 어려움 | 가능 | 풀 네이티브 | 불필요 (과투자) |

#### 권장 전략: PWA → TWA 2단계

**1단계: PWA 적용 (FE 작업, 1~2일)**

- [ ] `FE/transfermap/public/manifest.json` 생성
  - `name`, `short_name`, `start_url`, `display: "standalone"`, `theme_color`
  - 아이콘: 192×192, 512×512 PNG (maskable 포함)
- [ ] `vite-plugin-pwa` 설치 및 `vite.config.ts` 설정
  - Service Worker 자동 생성 (오프라인 캐싱)
- [ ] `index.html`에 `<link rel="manifest">` + iOS meta 태그 추가
- [ ] Lighthouse PWA 점수 확인 (설치 가능 조건 충족 여부)

**2단계: TWA로 Play Store 출시 (1~3일)**

- [ ] [Bubblewrap CLI](https://github.com/GoogleChromeLabs/bubblewrap) 설치
  ```
  npm i -g @bubblewrap/cli
  bubblewrap init --manifest https://your-domain.com/manifest.json
  bubblewrap build
  ```
- [ ] `assetlinks.json` 서버에 배포 (`/.well-known/assetlinks.json`)
  - TWA가 브라우저 UI 없이 실행되려면 도메인 인증 필수
- [ ] Google Play Console 등록 → APK/AAB 업로드

#### 주요 결정 사항

- **도메인**: 배포된 서버 URL 필요 (localhost 불가, HTTPS 필수)
- **오프라인 지원 범위**: 지도 타일/API 데이터 캐싱 수준 결정 필요
- **앱스토어 출시 여부**: TWA는 Play Store 정책상 "웹 앱 래퍼"로 거부될 수 있음
  - 실질적인 콘텐츠/기능이 있으면 통과 가능 (transfer-map은 해당)
- **네이티브 기능 필요 여부**: 푸시 알림 필요 시 Capacitor로 전환 고려

#### 즉시 할 수 있는 첫 번째 액션

- [ ] `vite-plugin-pwa` 설치 및 manifest 기본 설정 → 모바일 Chrome에서 "홈 화면에 추가" 테스트
